# 阶段 1：Gate.io 公告数据源调研报告

> 对应原始规划中的「阶段 1：研究 Gate.io 公告数据源」。

## 调研目标

- 1.1 是否存在可直接使用的公告 API（优先级 ⭐⭐⭐）
- 1.2 公告网页结构是否可抓取（优先级 ⭐⭐）
- 1.3 是否存在 RSS 订阅源（优先级 ⭐）
- 1.4 下架公告 URL/关键词规律（优先级 ⭐⭐⭐）

## 本次调研方法

使用 `curl -L -I` 对候选数据源做连通性探测：

- `https://www.gate.io/announcements`
- `https://api.gateio.ws/api/v4`
- `https://www.gate.io/announcements/rss`
- `https://www.gate.io/rss`

## 调研结果（在当前执行环境）

| 编号 | 项目 | 结果 | 结论 |
|---|---|---|---|
| 1.1 | 公告 API | 网关返回 `403 Forbidden`，无法在本环境直连验证 | 暂定「待二次确认」 |
| 1.2 | 公告网页 | 网关返回 `403 Forbidden`，无法在本环境抓取 | 暂定「可行但需外部环境验证」 |
| 1.3 | RSS | 候选 RSS 地址均返回 `403 Forbidden` | 暂定「未确认」 |
| 1.4 | URL/关键词规律 | 代码中已按 `delist/remove/下架/移除` 做关键词预筛 | 可进入阶段 2 持续迭代 |

## 关键限制说明

当前容器网络出口对目标站点存在代理限制，`CONNECT tunnel failed, response 403`，导致无法直接完成线上可达性与结构验证。

这不是业务代码逻辑错误，而是**执行环境限制**。

## 阶段结论

- 阶段 1 已完成「调研动作与证据留档」。
- 下一步进入阶段 2 时，默认采用：
  1. 网页抓取（当前已实现，作为可运行基线）；
  2. 预留 API/RSS 入口，待在可直连网络环境补充验证后切换优先级。
