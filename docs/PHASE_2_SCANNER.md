# 阶段 2：公告扫描模块实现记录

> 对应原始规划中的「阶段 2：实现公告扫描模块 scanner.py」。

## 本阶段目标

- 定时访问公告源并获得下架相关公告列表。
- 尽量避免单一数据源失败导致主流程中断。

## 已实现内容

1. 新增 `scan_announcements()` 多源扫描入口，按优先级尝试：
   - API（预留）
   - Web 抓取（当前主用）
   - RSS（预留）
2. 保持 `Announcement` 数据结构统一输出：`{id, title, url, date}`。
3. 加入扫描容错：某个源异常不会中断整体扫描，会自动尝试下一个源。
4. 保留 `history.json` 去重机制：`get_new_announcements()` 会过滤已处理公告 ID。

## 设计说明

- 当前可运行主路径是 Web 抓取。
- API/RSS 保留为阶段化扩展点，便于后续在可直连环境中接入。
- `requests`/`BeautifulSoup` 延迟到函数内导入，避免在依赖暂未安装时影响其它模块导入和工具脚本运行。

## 下一步（阶段 3）

- 强化公告正文解析准确率（减少误提取）。
- 增加解析单元测试样例（历史公告文本回放）。
